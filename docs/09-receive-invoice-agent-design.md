# 09 — 收票智能体业务流程设计

## 1. 收票智能体总览

收票智能体是与销项开票智能体对称的 **进项收票自动化系统**，核心职责是：

1. 通过诺诺网接口自动获取供应商开给本企业的进项发票
2. 智能识别供应商并比对待收票的进货单
3. 将发票明细智能分配到匹配的进货单
4. 按企业配置的粒度（大品类 / 具体规格）管理进项库存
5. 自动生成 ERP 进项发票记录
6. 核销待收票状态并写入进项发票台账

```
诺诺网进项发票接口 → 拉取进项发票数据 → 发票数据解析入库
  → 供应商智能识别 → 匹配待收票进货单 → 发票明细智能分配
  → 进项库存入库（大品类/具体规格可配） → 生成ERP进项发票
  → 核销待收票 → 写入进项发票台账 → 通知相关人员
```

### 2.2 进项发票获取策略

系统支持三种获取进项发票的方式，可并行使用：

```
┌── 获取方式 ──────────────────────────────────────────────────────┐
│                                                                  │
│  方式一：定时拉取（主动）                                          │
│  ├─ 定时任务：每 30 分钟执行一次                                   │
│  ├─ 调用诺诺网 queryInvoicesIncome 接口                          │
│  ├─ 按时间区间增量拉取（上次拉取时间 ~ 当前时间）                    │
│  ├─ 分页拉取，每页 50 条                                         │
│  └─ 适用场景：日常运营，批量处理                                   │
│                                                                  │
│  方式二：回调推送（被动）                                          │
│  ├─ 在诺诺网配置进项推送回调地址                                    │
│  ├─ 供应商开票后，诺诺网实时推送进项数据到本系统                      │
│  ├─ 延迟通常 < 5 分钟                                            │
│  └─ 适用场景：实时性要求高的场景                                   │
│                                                                  │
│  方式三：手动触发（补充）                                          │
│  ├─ 管理端提供"手动同步"按钮                                      │
│  ├─ 可指定发票代码+号码单张同步                                    │
│  ├─ 可指定日期区间批量同步                                        │
│  └─ 适用场景：遗漏补录、问题排查                                   │
│                                                                  │
│  去重机制：                                                       │
│  ├─ 唯一键：发票代码 + 发票号码 (invoice_code + invoice_number)    │
│  ├─ Redis Set 快速判重：recv_inv_exists:{tenantId}                │
│  └─ 数据库唯一索引兜底                                            │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘
```

### 2.3 供应商智能识别

```
进项发票上的销方信息
  │
  ├─ 提取关键字段
  │   ├─ seller_name: 销方名称（如"河北XX钢铁集团有限公司"）
  │   ├─ seller_tax_no: 销方税号（如"91130000XXXXXXXXXX"）
  │   ├─ seller_address: 销方地址
  │   └─ seller_bank_info: 销方银行信息
  │
  ├─ Step 1: 税号精确匹配
  │   查询 t_supplier WHERE tax_no = seller_tax_no
  │   │
  │   ├─ 匹配到 → 确认供应商 ✅
  │   │   (税号是唯一的，匹配到即可确认)
  │   │
  │   └─ 未匹配 → Step 2
  │
  ├─ Step 2: 名称相似度匹配
  │   │
  │   ├─ 完全相同：seller_name = supplier_name → 确认 ✅
  │   │
  │   ├─ 相似匹配：
  │   │   使用编辑距离(Levenshtein) + 分词匹配
  │   │   similarity ≥ 0.9 → 自动确认 ✅
  │   │   similarity 0.7-0.9 → 推荐候选，待人工确认
  │   │   similarity < 0.7 → 可能是新供应商
  │   │
  │   └─ 特殊处理：
  │       ├─ 去除"有限公司""有限责任公司""集团"等后缀后再比较
  │       ├─ 处理简称（如"宝钢" vs "宝山钢铁"）→ 需别名表支持
  │       └─ 处理集团子公司（如"XX集团XX分公司"）
  │
  ├─ Step 3: 未匹配处理
  │   │
  │   ├─ 标记为"待确认供应商"
  │   ├─ 提示是否新建供应商
  │   │   ├─ 自动从发票中提取供应商信息预填
  │   │   └─ 人工确认后保存
  │   └─ 发送通知给采购人员确认
  │
  └─ 供应商别名学习
      ├─ 每次人工确认后，将发票上的名称作为供应商别名保存
      ├─ 后续相同名称自动匹配
      └─ 提高识别率：首次 80% → 运行 3 个月后 > 98%
```

### 2.4 进货单匹配算法

```
┌── 进货单匹配引擎 ───────────────────────────────────────────────┐
│                                                                 │
│  输入：                                                         │
│  ├─ 进项发票（含明细行：品名、规格、数量、单价、金额、税率）        │
│  └─ 候选进货单列表（该供应商下所有 status = PENDING_INVOICE 的单）  │
│                                                                 │
│  匹配评分维度（加权得分，满分 100）：                               │
│  ┌─────────────────────────────────────────────────────────┐    │
│  │                                                         │    │
│  │  1. 金额匹配度（权重 40%）                                │    │
│  │     ├─ 发票金额 = 进货单金额 → 40 分                      │    │
│  │     ├─ 差异 ≤ 0.01 (尾差) → 39 分                        │    │
│  │     ├─ 差异 ≤ 1% → 35 分                                 │    │
│  │     ├─ 差异 ≤ 5% → 20 分                                 │    │
│  │     └─ 差异 > 5% → 0 分                                  │    │
│  │                                                         │    │
│  │  2. 品名匹配度（权重 25%）                                │    │
│  │     ├─ 发票品名完全包含进货单品名 → 25 分                  │    │
│  │     ├─ 品名属于同一品类大类 → 20 分                        │    │
│  │     └─ 不匹配 → 0 分                                     │    │
│  │                                                         │    │
│  │  3. 时间接近度（权重 15%）                                │    │
│  │     ├─ 发票日期在进货日期 ± 7 天 → 15 分                  │    │
│  │     ├─ ± 30 天 → 10 分                                   │    │
│  │     ├─ ± 90 天 → 5 分                                    │    │
│  │     └─ > 90 天 → 0 分                                    │    │
│  │                                                         │    │
│  │  4. 规格匹配度（权重 10%）                                │    │
│  │     ├─ 规格完全一致 → 10 分                               │    │
│  │     ├─ 部分一致 → 5 分                                    │    │
│  │     └─ 不一致 / 无规格 → 0 分                              │    │
│  │                                                         │    │
│  │  5. 数量/重量接近度（权重 10%）                            │    │
│  │     ├─ 差异 ≤ 1% → 10 分                                 │    │
│  │     ├─ 差异 ≤ 5% → 7 分                                  │    │
│  │     ├─ 差异 ≤ 10% → 3 分                                 │    │
│  │     └─ 差异 > 10% → 0 分                                 │    │
│  │                                                         │    │
│  └─────────────────────────────────────────────────────────┘    │
│                                                                 │
│  匹配结果判定：                                                  │
│  ├─ 总分 ≥ 85 → AUTO_MATCH（自动匹配，直接分配）                 │
│  ├─ 总分 60-84 → SUGGEST_MATCH（推荐匹配，需人工确认）            │
│  ├─ 总分 < 60 → NO_MATCH（无法匹配，人工处理）                   │
│  └─ 存在多个 ≥ 85 的候选 → 取最高分且唯一时自动匹配，             │
│     否则列出候选待人工选择                                        │
│                                                                 │
│  特殊场景处理：                                                  │
│  ├─ 一票多单：发票金额 > 单个进货单 → 拆分分配到多张进货单          │
│  ├─ 多票一单：多张发票 → 累计对应一张进货单 → 合并核销              │
│  └─ 无单匹配：供应商存在但无待收票单 → 暂存为"未分配进项发票"       │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.5 发票明细智能分配

```
匹配完成后，将发票明细行具体分配到进货单明细行

场景一：1 张发票 → 1 张进货单 (1:1)
──────────────────────────────────
  发票明细行                    进货单明细行
  ┌─────────────────┐          ┌─────────────────┐
  │ 热轧卷板 12.5吨  │ ──────▶ │ 热轧卷板 12.5吨  │
  │ ¥52,500         │          │ ¥52,500         │
  ├─────────────────┤          ├─────────────────┤
  │ 冷轧卷板 8.0吨   │ ──────▶ │ 冷轧卷板 8.0吨   │
  │ ¥40,000         │          │ ¥40,000         │
  └─────────────────┘          └─────────────────┘
  分配方式：逐行对应，品名+规格匹配

场景二：1 张发票 → N 张进货单 (1:N)
──────────────────────────────────
  发票                          进货单A (¥52,500)
  ┌─────────────────┐          ┌─────────────────┐
  │ 热轧卷板 25.0吨  │ ──拆分──▶│ 热轧卷板 12.5吨  │
  │ ¥105,000        │          │ ¥52,500         │
  └─────────────────┘          └─────────────────┘
                               进货单B (¥52,500)
                               ┌─────────────────┐
                        ──────▶│ 热轧卷板 12.5吨  │
                               │ ¥52,500         │
                               └─────────────────┘

  分配算法：
  1. 按进货单日期正序排列
  2. 依次填充，直至发票明细行数量/金额分配完毕
  3. 尾行可能产生部分分配

场景三：N 张发票 → 1 张进货单 (N:1)
──────────────────────────────────
  发票A (¥52,500)               进货单 (¥105,000)
  ┌─────────────────┐          ┌─────────────────┐
  │ 热轧卷板 12.5吨  │ ──合并──▶│ 热轧卷板 25.0吨  │
  │ ¥52,500         │          │ 已收票 ¥105,000  │
  └─────────────────┘          │ 待收票 ¥0        │
  发票B (¥52,500)               │ 状态：已全部收票  │
  ┌─────────────────┐          └─────────────────┘
  │ 热轧卷板 12.5吨  │ ────────▶
  │ ¥52,500         │
  └─────────────────┘

  分配规则：
  1. 多张发票分配到同一进货单
  2. 累计已收票金额
  3. 当 已收票金额 ≥ 进货单金额 时，进货单标记"已全部收票"

分配约束：
  ├─ 发票明细金额必须全部分配完（不允许有剩余未分配金额）
  ├─ 分配到进货单的金额不得超过进货单剩余待收票金额
  │  （除非开启了"允许超额收票"配置——用于处理发票金额合理误差）
  ├─ 超额容差可配：默认 ±0.5% 或 ±100 元（取小值）
  └─ 分配结果需通过"分配校验引擎"校验后方可确认
```

### 2.6 进项库存入库策略

这是收票智能体的关键可配置项，直接影响销项开票时的进项匹配精度。

```
┌── 进项库存粒度配置 ──────────────────────────────────────────────┐
│                                                                 │
│  配置层级：租户级（每个钢贸企业可独立配置）                          │
│  配置项：input_inventory_granularity                             │
│                                                                 │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │                                                          │   │
│  │  模式一：具体规格模式 (SPECIFICATION)                      │   │
│  │  ──────────────────────                                  │   │
│  │  库存维度：品名 + 规格型号 + 税率                           │   │
│  │  示例入库：                                               │   │
│  │    ├─ 热轧卷板 | Q235B 5.75*1500*C | 13% | 12.5吨       │   │
│  │    ├─ 热轧卷板 | Q235B 4.75*1500*C | 13% | 8.0吨        │   │
│  │    └─ 冷轧卷板 | SPCC 1.0*1250*C   | 13% | 5.0吨        │   │
│  │                                                          │   │
│  │  优点：                                                   │   │
│  │    ├─ 进销项精确对应，税务风险最低                           │   │
│  │    └─ 适合大客户"怎么买怎么卖怎么开"的场景                   │   │
│  │  缺点：                                                   │   │
│  │    ├─ 库存碎片化，可能出现某规格库存不足但其他有余             │   │
│  │    └─ 管理复杂度高                                        │   │
│  │                                                          │   │
│  │  模式二：大品类模式 (CATEGORY)                              │   │
│  │  ──────────────────────                                  │   │
│  │  库存维度：品类大类 + 税率                                 │   │
│  │  品类大类映射（可配置）：                                   │   │
│  │    ├─ 热轧卷板（含所有热轧卷板规格）                        │   │
│  │    ├─ 冷轧卷板（含所有冷轧卷板规格）                        │   │
│  │    ├─ 镀锌卷板（含所有镀锌卷板规格）                        │   │
│  │    ├─ 中厚板（含所有中厚板规格）                            │   │
│  │    └─ 型材（含 H 型钢、角钢、槽钢等）                      │   │
│  │                                                          │   │
│  │  示例入库：                                               │   │
│  │    ├─ 热轧卷板 | 13% | 20.5吨 (合并了所有规格)            │   │
│  │    └─ 冷轧卷板 | 13% | 5.0吨                             │   │
│  │                                                          │   │
│  │  优点：                                                   │   │
│  │    ├─ 库存利用率高，减少碎片                               │   │
```

### 2.7 ERP 进项发票生成

```
发票明细分配确认后，自动生成 ERP 进项发票记录

Step 1: 组装 ERP 进项发票
  ├─ 发票头信息（从诺诺网数据映射）
  │   ├─ 发票代码、发票号码、开票日期
  │   ├─ 销方（供应商）信息
  │   ├─ 购方（本企业）信息
  │   ├─ 合计金额（不含税）、税额、价税合计
  │   └─ 发票类型、发票状态
  │
  ├─ 发票明细行（从分配结果映射）
  │   ├─ 品名、规格、单位、数量、单价、金额、税率、税额
  │   └─ 关联进货单号、进货单明细行号
  │
  └─ 关联信息
      ├─ 供应商ID
      ├─ 进货单ID列表
      └─ 原始诺诺网数据快照（备查）

Step 2: 核销进货单待收票
  ├─ 更新 t_purchase_order.invoiced_amount += 本次发票金额
  ├─ 更新 t_purchase_order_item.invoiced_quantity += 本次分配数量
  ├─ 判断核销状态
  │   ├─ 已收票金额 ≥ 进货单金额 → invoice_status = FULLY_INVOICED
  │   ├─ 已收票金额 > 0 但 < 进货单金额 → invoice_status = PARTIAL_INVOICED
  │   └─ 已收票金额 = 0 → invoice_status = PENDING_INVOICE
  └─ 更新时使用乐观锁（version 字段）防并发

Step 3: 写入进项发票台账
  ├─ t_input_invoice_ledger 记录完整的进项台账
  │   ├─ 每条记录对应一张进项发票
  │   ├─ 包含：认证状态、抵扣状态、入账期间
  │   ├─ 支持按月份/供应商/品类汇总查询
  │   └─ 作为税务申报的数据基础
  │
  └─ 更新 t_tax_account（税务账户）
      ├─ cumulative_input_tax += 本次进项税额
      └─ 重新计算 tax_burden_rate

Step 4: 通知相关人员
  ├─ 采购员：你的进货单 PO20250325001 已收到供应商发票
  ├─ 财务人员：新进项发票已入库，进项台账已更新
  └─ 如有异常（金额不匹配等）：发送告警通知
```

### 2.8 异常场景处理

| 异常场景 | 处理方式 | 自动/人工 |
|---------|---------|----------|
| 供应商无法识别 | 标记待确认，提示新建供应商 | 人工 |
| 无匹配的进货单 | 暂存为"未分配进项发票"，等待后续匹配 | 半自动 |
| 发票金额与进货单差异 > 5% | 进入人工审核队列 | 人工 |
| 发票品名与进货单品名不符 | 品类映射匹配，仍不符则人工 | 半自动 |
| 重复发票 | 幂等拦截，提示已存在 | 自动 |
| 发票被红冲 | 自动冲回：释放进项库存、回退核销、删除台账 | 自动 |
| 诺诺网接口超时 | 重试 3 次，仍失败则记录失败日志待下次调度 | 自动 |
| 进货单已关闭/取消 | 发票标记"单据已关闭"，需人工重新分配 | 人工 |
| 税率不一致 | 告警提示，可能存在税率变更 | 人工确认 |

### 2.9 状态机定义

#### 进项发票状态机

```
                    ┌────────────┐
                    │  RECEIVED  │  从诺诺网获取
                    └─────┬──────┘
                          │ 供应商识别
                ┌─────────▼──────────┐
                │  SUPPLIER_MATCHED  │  已匹配供应商
                └─────────┬──────────┘
                          │ 进货单匹配
             ┌────────────▼───────────┐
             │  ORDER_MATCHING        │  进货单匹配中
             └──────┬─────────┬───────┘
                    │         │
           自动匹配 │         │ 无法自动匹配
                    ▼         ▼
          ┌────────────┐  ┌───────────────┐
          │ ALLOCATED  │  │ PENDING_MANUAL│  待人工分配
          │ 已分配     │  └───────┬───────┘
          └─────┬──────┘         │ 人工分配完成
                │                ▼
                │         ┌────────────┐
                │         │ ALLOCATED  │
                │         └─────┬──────┘
                │               │
                ▼               ▼
          ┌───────────────────────┐
          │  ERP_GENERATED        │  ERP进项发票已生成
          └──────────┬────────────┘
                     │
                     ▼
          ┌───────────────────────┐
          │  WRITE_OFF_COMPLETE   │  核销完成（待收票已核销，台账已写入）
          └──────────┬────────────┘
                     │
                     ▼
          ┌───────────────────────┐
          │  ARCHIVED             │  归档（月末结账后）
          └───────────────────────┘

  异常分支：
  RECEIVED → SUPPLIER_UNMATCHED → [人工确认] → SUPPLIER_MATCHED
  任意状态 → VOIDED（发票被红冲/作废）
```

#### 进货单收票状态机

```
PENDING_INVOICE → PARTIAL_INVOICED → FULLY_INVOICED → ARCHIVED
      ↑                                                  │
      └──── INVOICE_VOIDED（发票红冲后回退） ←──────────────┘
```

## 4. 与销项开票智能体的联动

```
收票智能体                                销项开票智能体
┌─────────────────┐                      ┌─────────────────┐
│ 进项发票入库     │                      │                 │
│ 更新进项库存     │ ────── MQ 事件 ─────▶│ 监听进项到货事件  │
│ (品名/规格/数量)  │  INPUT_INVENTORY    │ 扫描待开票队列   │
│                 │  .REPLENISH          │ 自动重试匹配     │
└─────────────────┘                      └─────────────────┘

联动场景：
1. 收票入库后，销项开票引擎自动扫描是否有等待进项的待开票申请
2. 如果新进项刚好满足某个待开票申请 → 自动触发开票
3. 减少客户等待时间，提高自动化率
```
