# 06 — 第三方集成设计

## 1. 诺诺网（电子税务局开票）

### 1.1 集成架构

```
┌── invoice-service ──────────────────────────────────────┐
│                                                         │
│  InvoiceIssuanceService                                 │
│       │                                                 │
│       ▼                                                 │
│  NuonuoGateway (封装层)                                  │
│  ├─ Token 管理（自动刷新，缓存 TTL=2h）                    │
│  ├─ 请求签名（appKey + appSecret + timestamp）           │
│  ├─ 请求/响应日志记录                                     │
│  ├─ 重试机制（3次，指数退避 1s/2s/4s）                     │
│  ├─ 熔断降级（Sentinel，10s 窗口内失败 > 50% 则熔断）      │
│  └─ 响应解析 + 异常转换                                   │
│       │                                                 │
│       ▼                                                 │
│  HTTP Client (OkHttp / Spring WebClient)                │
│  ├─ 连接池: maxIdleConnections=20, keepAlive=60s        │
│  ├─ 超时: connectTimeout=5s, readTimeout=30s            │
│  └─ TLS 1.2+                                           │
│                                                         │
└──────────────────────┬──────────────────────────────────┘
                       │
                       ▼
              ┌── 诺诺网开放平台 ──┐
              │  open.nuonuo.com  │
              └───────────────────┘
```

### 1.2 核心接口对接

#### 1.2.1 销项开票接口

| 诺诺网接口 | 用途 | 调用时机 |
|-----------|------|---------|
| getMerchantToken | 获取授权 Token | 启动时 + Token 过期前 |
| requestBillingNew | 请求开票 | 开票运算完成后 |
| deliveryInvoice | 发票交付 | 开票成功后获取 PDF/OFD |
| reInvoice | 发票重开 | 红冲后重开 |
| queryInvoiceResult | 查询开票结果 | 回调超时时主动查询 |

#### 1.2.2 进项收票接口（收票智能体使用）

| 诺诺网接口 | 用途 | 调用时机 |
|-----------|------|---------|
| queryInvoicesIncome | 查询进项发票列表 | 定时拉取（每30分钟）/ 手动触发 |
| queryInvoiceDetail | 查询进项发票明细 | 按需获取发票完整明细 |
| queryInvoiceStatistics | 进项发票统计 | 台账对账、月末汇总 |
| invoiceAuthStatus | 查询发票认证状态 | 同步认证状态到台账 |

**进项发票拉取流程**

```
input-service (收票引擎)
  │
  ├─ 定时任务 InvoicePullJob (每30分钟)
  │   ├─ 获取上次拉取时间 (Redis: recv:pull:lastTime:{tenantId})
  │   ├─ 调用 queryInvoicesIncome(startDate, endDate)
  │   ├─ 分页循环拉取 (pageSize=50)
  │   ├─ 幂等校验 (Redis Set + DB 唯一键)
  │   ├─ 解析并入库 t_received_invoice + t_received_invoice_item
  │   ├─ 更新拉取时间
  │   └─ 发送 MQ 事件: RECEIVE_INVOICE.RECEIVED
  │
  └─ 诺诺网回调推送 (实时)
      ├─ 诺诺网配置回调地址: /callback/nuonuo/input-invoice
      ├─ 验证回调签名
      ├─ 解析并入库
      └─ 发送 MQ 事件: RECEIVE_INVOICE.RECEIVED
```

### 1.3 回调处理

```
诺诺网回调 → Gateway → invoice-service

处理流程：
1. 验证回调签名（防伪造）
2. 幂等校验（serialNo 去重）
3. 解析发票信息（发票代码、号码、日期）
4. 下载发票 PDF/OFD → 存储到 MinIO/OSS
5. 更新 t_invoice_apply 状态
6. 同步更新 t_delivery_order 已开票金额
7. 确认进项库存锁定（TCC Confirm）
8. 更新税务账户（t_tax_account）
9. 同步到 ES
10. WebSocket 推送客户
11. ACK 回调

超时兜底：
- 如果 5 分钟未收到回调，定时任务主动调用 queryInvoiceResult
- 如果查询也失败，标记为需人工确认
```

### 1.4 异常处理映射

| 诺诺网错误码 | 含义 | 系统处理 |
|-------------|------|---------|
| E0000 | 成功 | 正常流程 |
| E1001 | 重复开票 | 幂等返回已有发票 |
| E1002 | 购方信息有误 | 返回具体错误，提示客户修改 |
| E1003 | 税盘离线 | 重试 3 次，仍失败进人工 |
| E1004 | 开票额度不足 | 进人工处理 |
| 网络超时 | 接口不可达 | 重试 3 次 → 主动查询 → 人工 |

## 2. 电子签章平台

### 2.1 集成方案

支持对接 **e签宝** 和 **法大大** 两家平台（策略模式切换）。

```
┌── contract-service ─────────────────────────────────────┐
│                                                         │
│  ContractSignService                                    │
│       │                                                 │
│       ▼                                                 │
│  ESignGateway (策略模式)                                  │
│  ├─ ESignBaoStrategy (e签宝)                             │
│  └─ FaDaDaStrategy (法大大)                              │
│                                                         │
│  核心功能：                                               │
│  ├─ 创建签署流程                                          │
│  ├─ 生成签署链接（H5/小程序/短信）                          │
│  ├─ 查询签署状态                                          │
│  ├─ 下载已签署文件                                        │
│  └─ 验证签署有效性                                        │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 2.2 签署流程

```
1. 生成合同 PDF
   ├─ 根据模板 + 业务数据生成 PDF (iText / Apache POI + LibreOffice)
   ├─ 在 PDF 中标记签署位（坐标占位）
   └─ 上传到签章平台

2. 创建签署流程
   ├─ 指定签署方：甲方（我方自动签）+ 乙方（客户）
   ├─ 设置签署顺序
   └─ 设置回调地址

3. 我方自动盖章
   ├─ 使用预录入的企业印章 ID
   └─ 调用 API 自动签署

4. 发送签署通知给客户
   ├─ 短信 + 站内消息
   └─ 包含签署链接

5. 客户签署
   ├─ 手写签名 / CA 数字证书 / 短信验证码
   └─ 签署完成回调

6. 回调处理
   ├─ 下载已签署 PDF
   ├─ 更新合同状态
   └─ 触发后续开票流程
```

### 2.3 线下签署替代方案

对于不愿或无法使用电子签章的客户：

```
1. 系统生成合同 PDF（含签署区留白）
2. 客户下载 PDF
3. 线下打印 → 盖章
4. 扫描/拍照 → 上传
5. 系统进行 OCR 识别
   ├─ 识别印章位置
   ├─ 提取印章文字
   ├─ 与客户企业名称比对
   └─ 输出置信度分数
6. 置信度 > 0.8 → 自动审核通过
7. 置信度 ≤ 0.8 → 转人工审核
8. 审核通过 → 合同生效
```

## 3. OCR 识别

### 3.1 使用场景

| 场景 | 识别内容 | 服务 |
|------|---------|------|
| 第三方付款授权书 | 委托方、受托方、金额、日期 | 阿里云/腾讯 OCR |
| 线下盖章合同 | 印章文字、印章位置 | 印章专用 OCR |
| 进项发票录入 | 发票全字段 | 增值税发票 OCR |

### 3.2 集成方式

```
┌── file-service ──────────────────────────────────────┐
│                                                      │
│  OcrService                                          │
│  ├─ InvoiceOcrStrategy (发票识别)                     │
│  ├─ SealOcrStrategy (印章识别)                        │
│  └─ DocumentOcrStrategy (文档识别)                    │
│                                                      │
│  结果校验层：                                          │
│  ├─ 自动字段比对                                      │
│  ├─ 置信度判定（> 0.8 自动通过）                       │
│  └─ 异常标记 → 人工复核                                │
│                                                      │
└──────────────────────────────────────────────────────┘
```

## 4. 对象存储 (MinIO / 阿里云 OSS)

### 4.1 Bucket 规划

| Bucket | 用途 | 访问策略 | 保留策略 |
|--------|------|---------|---------|
| invoice-pdf | 发票 PDF/OFD | 客户鉴权后读 | 永久 |
| contract-files | 合同文件 | 签署方鉴权后读 | 永久 |
| auth-files | 授权书文件 | 内部只读 | 永久 |
| templates | 合同模板 | 内部读 | 永久 |
| temp-files | 临时文件 | 内部读写 | 7天自动清理 |

### 4.2 文件访问安全

- 所有文件通过 **预签名URL** 访问，有效期 15 分钟
- 下载前校验用户权限（只能下载自己的发票/合同）
- 文件上传大小限制：PDF 20MB，图片 10MB
- 病毒扫描：上传后异步扫描
