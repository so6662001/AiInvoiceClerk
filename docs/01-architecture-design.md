# 01 — 系统架构设计

## 1. 架构总览

系统采用 **微服务 + 事件驱动** 架构，基于 Spring Cloud Alibaba 生态，前端使用 Vue 3 SPA，通过 API Gateway 统一接入。

## 2. 微服务拆分

| 服务名 | 职责 | 关键能力 |
|--------|------|---------|
| **gateway-service** | API 网关 | 统一鉴权、限流（令牌桶 1w QPS）、路由、灰度发布 |
| **customer-service** | 客户管理 | 客户档案、开票策略配置（先款后票/先票后款）、客户分级（大客户/经销商/用料企业） |
| **order-service** | 单据管理 | 提货单、销售单、付款记录关联 |
| **invoice-service** | 开票核心 | 开票申请、开票运算引擎、进项匹配、税负调控、诺诺网对接 |
| **input-service** | 进项管理 | 进项发票库存、品类价格映射、库存锁定/释放 |
| **contract-service** | 合同管理 | 合同模板、电子签章、线下盖章上传、合同状态流转 |
| **payment-service** | 付款管理 | 付款记录、对公/对私识别、多笔打款聚合校验 |
| **notify-service** | 通知服务 | 短信/邮件/站内信/WebSocket 推送 |
| **file-service** | 文件服务 | PDF 生成、文件上传下载、电子签章文件管理 |
| **auth-service** | 认证授权 | JWT + OAuth2、RBAC 权限 |

## 4. 服务间通信

| 场景 | 方式 | 说明 |
|------|------|------|
| 同步查询（如查客户信息） | OpenFeign + Sentinel 熔断 | 超时 3s，熔断阈值 50%，降级返回缓存数据 |
| 异步事件（如开票完成通知） | RocketMQ 事务消息 | 保证消息最终一致性 |
| 分布式事务（如进项锁定+开票） | Seata AT 模式 | 自动补偿，兜底人工对账 |
| 实时推送（如开票进度） | WebSocket + STOMP | 通过 notify-service 统一推送 |

## 6. 核心设计原则

1. **领域驱动设计 (DDD)**：以开票领域为核心，划分清晰的限界上下文
2. **事件驱动架构 (EDA)**：核心流程通过事件解耦，提高系统弹性
3. **CQRS 读写分离**：开票申请列表查询走 ES，写操作走 MySQL
4. **幂等性设计**：所有开票接口支持幂等重试，防止重复开票
5. **最终一致性**：通过事务消息 + 对账任务保障数据最终一致
6. **可观测性**：全链路 Trace + Metrics + Logging 三位一体
